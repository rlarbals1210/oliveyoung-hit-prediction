# 올리브영 신상품 히트 판별

> 출시 후 첫 2주의 리뷰·평점 데이터만으로 카테고리 상위권 상품을 구분할 수 있는지 검증한 프로젝트 — 실시간 예측이 아니라 단일 시점 순위 스냅샷 기준의 **소급 판별**입니다

📊 **포트폴리오 상세 (분석 스토리·인사이트)**: [Notion 프로젝트 페이지](https://gyumin-kim.notion.site/eebf07a35f5182dfaf8e0105c64a2976)

## 문제 정의

올리브영에서는 매월 수십 개의 신상품이 출시되지만, 그중 일부만 카테고리 상위에 안착합니다. 이 프로젝트는 **출시 직후 초기 시그널**(리뷰 속도, 별점 분산, 텍스트 토픽 등)만으로 카테고리 상위권 상품과 그렇지 않은 상품을 구분할 수 있는지 검증합니다.

### 설계 성격 — 소급 판별

순위는 **2026-04-27 단일 스냅샷**이고, 14일 피처 구간은 상품별 `launch_date_est`(수집된 리뷰 중 `MIN(written_at)`으로 추정한 출시일) 기준입니다. 두 시점 사이 간격이 상품마다 달라 **모든 상품에 공통으로 적용되는 예측 지평이 없습니다.**

따라서 '2주 데이터로 N개월 뒤 순위를 예측한다'는 실시간 예측 과제가 아니라, 이미 확정된 순위를 초기 신호로 소급해 구분할 수 있는지를 본 것입니다. 여기서 구분되지 않으면 실시간 예측은 더 어렵다는 판단의 근거로 씁니다.

라벨은 `is_hit = (rank <= 30)`, `rank >= 71`을 논히트로 두고 **31~70위는 모호성 제거를 위해 제외**합니다. 여기에 14일 구간 리뷰가 0건인 상품 1개를 추가로 빼 최종 분석 표본은 119개(히트 60 / 논히트 59)입니다.

## 데이터

- **출처**: 올리브영 (직접 크롤링, 2026-04-27 기준)
- **범위**: 스킨케어·색조 메이크업 카테고리 베스트셀러 Top 100 × 2카테고리
- **수집 도구**: Playwright 기반 3계층 크롤러 (랭킹 → 상품 상세 → 리뷰)
- **저장·분석**: SQLite 원본 적재 + DuckDB JOIN·윈도우 함수·QUALIFY 피처 쿼리

| 테이블 | 행 수 | 설명 |
|---|---|---|
| `products` | 200개 | 상품 메타데이터 (이름·브랜드·가격·평점 등) |
| `rankings` | 200개 | 카테고리별 랭킹 — **2026-04-27 단일 스냅샷** (시계열 아님) |
| `reviews` | 18,695건 | 상품당 평균 93건, 2022~2026년 |

## 프로젝트 구조

```
oliveyoung-hit-prediction/
├── data/
│   ├── raw/          # 크롤링 원본 (SQLite, CSV) — git 미커밋
│   ├── interim/      # 중간 정제 데이터
│   └── processed/    # 모델 입력용 피처 테이블
├── notebooks/        # 탐색·실험 (사고 흐름 기록)
│   ├── 01_eda.ipynb                  # 데이터 구조·분포·히트 라벨 정의
│   ├── 02_features.ipynb             # 14일 구간 피처 엔지니어링
│   ├── 03_modeling.ipynb             # 로지스틱 회귀 베이스라인
│   ├── 04_text_analysis.ipynb        # BERTopic 토픽·텍스트 피처
│   ├── 05_modeling_lgbm.ipynb        # LightGBM·SHAP 해석
│   ├── 06_error_analysis.ipynb       # 오류군 분리(조용한 만점형·분산형)
│   ├── 07_validation.py              # 5x20 반복 교차검증 — 단일 분할 개선의 재현성 검증
│   ├── 08_window_experiment.py       # 관찰 기간 14일 vs 28일 비교
│   └── 08b_interaction_experiment.py # 상호작용 피처 처방 실험
├── src/              # 재사용 가능한 모듈
│   ├── crawler/      # ranking / product / review
│   ├── db/           # 스키마 정의
│   └── features/     # 피처 빌더
├── reports/
│   └── figures/      # 분석 시각화
└── tests/
```

## 분석 접근

| 단계 | 내용 | 산출물 |
|---|---|---|
| 데이터 수집 | 카테고리 랭킹 + 상품 상세 + 리뷰 크롤링 | SQLite DB |
| EDA | 가격·평점·리뷰 수 분포, 카테고리별 차이 | `01_eda.ipynb` |
| 피처 엔지니어링 | 리뷰 속도, 별점 드리프트, 텍스트 토픽 등 | `product_features` 테이블 |
| 베이스라인 모델 | 로지스틱 회귀, 피처 중요도 해석 | `03_modeling.ipynb` |
| 텍스트 분석 | BERTopic 토픽 모델링, 감성 분석 | 추가 피처 |
| 결과 정리 | 시각화·블로그 포스팅·발표 자료 | `reports/` |
